# Aurelia Disaster Recovery & Restore Runbook

> **CRITICAL OPERATIONAL SAFETY RULE**  
> **NEVER run a restore against the production project (`upzkcqovqstfsizerulx`)!**  
> Do not execute destructive SQL, reset the production database, delete remote files, or overwrite real user data.  
> This runbook is intended solely for recovering to a clean, newly provisioned disaster-recovery project or isolated staging environment.

---

## 1. Overview & Recovery Objectives

This runbook outlines the exact step-by-step procedure to restore Aurelia's database schema, application records, recipe photography, and service configuration from a verified backup archive generated by `scripts/backup/backup.ts`.

### Backup Archive Directory Structure
Each backup is timestamped and saved outside the repository at `%USERPROFILE%\AureliaBackups\<TIMESTAMP>\`:

```text
%USERPROFILE%\AureliaBackups\<TIMESTAMP>\
  ├── manifest.json                    # Cryptographic SHA-256 manifest & table inventory
  ├── schema/
  │   ├── consolidated_schema.sql      # Complete unified schema (DDL, RLS, functions, triggers)
  │   └── migrations/                  # Full sequence of Supabase migrations (00001 to 00006)
  ├── data/
  │   ├── restore-data.sql             # Dependency-ordered SQL INSERT script for all 21 tables
  │   └── <table_name>.json            # Individual JSON data dumps for each table
  ├── storage/
  │   ├── storage-inventory.json       # Inventory of image files, sizes, MIME types, and hashes
  │   └── recipe-images/               # Downloaded recipe photography files
  │       └── <user_id>/<file_name>
  ├── auth/
  │   └── users-inventory.json         # Safe user metadata (strictly excluding password hashes)
  └── config/
      └── disaster-recovery-config.json # Required environment variables and dashboard settings
```

## 2. Pre-Flight Verification (Step 0)

Before initiating recovery, cryptographically verify the integrity of the backup archive to guarantee no files are missing or corrupted:

```powershell
# From the repository root (C:\RecipeVault  mobile version):
npx tsx scripts/backup/verify-backup.ts --dir "C:\Users\<username>\AureliaBackups\<TIMESTAMP>"
```

### Expected Output:
- `All 38 files present with verified SHA-256 checksums.`
- `Verified 21 tables containing 663 total records.`
- `Verified 6 image objects (1.42 MB).`
- `[VERIFICATION PASSED] Backup is 100% complete and cryptographically sound.`

If any checksum fails or files are missing, do not proceed with that archive; use the previous verified backup run.

## 4. Rebuilding Database Schema (Step 2)

The database schema must be created prior to inserting data. All custom enums, tables, functions, triggers, and Row Level Security policies are restored via the consolidated schema script.

### Method A: Via Supabase SQL Editor (Recommended)
1. In the target Supabase Dashboard, open the **SQL Editor**.
2. Open `schema/consolidated_schema.sql` from your backup folder in a text editor.
3. Paste the contents into the SQL Editor and click **Run**.
4. Confirm execution succeeds without errors.

### Method B: Via Supabase CLI
```powershell
npx supabase link --project-ref <new-project-ref>
npx supabase db push
```

### Verification Check:
In the Dashboard under **Database -> Tables**, confirm all **21 application tables** are present:
- `profiles`, `recipes`, `ingredients`, `recipe_ingredients`, `recipe_instructions`
- `collections`, `collection_recipes`, `tags`, `recipe_tags`, `favorites`
- `shopping_lists`, `shopping_list_items`, `cooking_sessions`, `meal_plans`, `meal_plan_items`
- `user_preferences`, `ai_conversations`, `ai_messages`, `recipe_versions`, `recipe_sources`, `ai_rate_limits`

## 5. Restoring Application Data (Step 3)

Data must be restored in foreign-key dependency order to satisfy referential integrity. The generated `data/restore-data.sql` script is pre-sorted in exact dependency order and wrapped with `SET session_replication_role = replica;` to safely disable trigger loops during insertion.

### Table Dependency Hierarchy:
1. **Level 1 (Independent / User Root)**: `profiles`, `ingredients`, `tags`, `user_preferences`, `ai_rate_limits`
2. **Level 2 (Core Entities)**: `recipes`, `collections`, `shopping_lists`, `meal_plans`
3. **Level 3 (Junctions & Children)**: `recipe_ingredients`, `recipe_instructions`, `collection_recipes`, `recipe_tags`, `favorites`, `shopping_list_items`, `cooking_sessions`, `recipe_versions`, `recipe_sources`, `ai_conversations`
4. **Level 4 (Grandchildren)**: `meal_plan_items`, `ai_messages`

### Execution:
1. In the target Supabase Dashboard **SQL Editor**, open `data/restore-data.sql`.
2. Click **Run**.
3. Verify that all INSERT operations complete successfully.

### Row Count Verification Query:
Run the following SQL in the target project to verify row counts match the backup manifest:

```sql
SELECT 
  table_name,
  (xpath('/row/c/text()', query_to_xml(format('select count(*) as c from %I.%I', table_schema, table_name), false, true, '')))[1]::text::int AS row_count
FROM information_schema.tables 
WHERE table_schema = 'public' AND table_type = 'BASE TABLE'
ORDER BY table_name;
```

## 6. Restoring Recipe Photography & Storage Objects (Step 4)

Database records reference image URLs under the `recipe-images` bucket. The bucket was created by `schema/consolidated_schema.sql` (Migration 00002).

### Automated Storage Upload:
Run the restore helper with the target project's credentials:

```powershell
$env:RESTORE_TARGET_SUPABASE_URL = "https://<new-ref>.supabase.co"
$env:RESTORE_TARGET_SERVICE_ROLE_KEY = "<new-service-role-key>"

npx tsx scripts/backup/restore.ts --dir "C:\Users\<username>\AureliaBackups\<TIMESTAMP>"
```

### Manual Upload Alternative (Dashboard):
1. In the target Supabase Dashboard, navigate to **Storage -> Buckets -> recipe-images**.
2. For each folder in `<backupDir>\storage\recipe-images\<user_id>\`:
   - Create a folder matching `<user_id>`.
   - Upload the corresponding recipe photography files into that folder.

### Public Image Accessibility Check:
Test accessing any restored image in your browser:
`https://<new-ref>.supabase.co/storage/v1/object/public/recipe-images/<user_id>/<file_name>`  
Confirm the image renders with HTTP 200.

## 7. Auth & Service Configuration (Manual Dashboard Steps) (Step 5)

Supabase-managed authentication internals (passwords, encryption keys, and Google OAuth client secrets) are not exportable via raw SQL and must be reconfigured in the Supabase Dashboard:

### A. Authentication Providers
1. Go to **Authentication -> Providers -> Email**:
   - Ensure Email provider is **Enabled**.
   - Set "Confirm email" according to your environment policy.
2. Go to **Authentication -> Providers -> Google**:
   - Enable Google provider.
   - Input your Google Cloud OAuth **Client ID** and **Client Secret**.
   - Copy the Supabase Callback URL (`https://<new-ref>.supabase.co/auth/v1/callback`) into the Google Cloud Console Authorized Redirect URIs.

### B. URL & Redirect Configuration
In **Authentication -> URL Configuration**:
- **Site URL**: `https://aurelia-recipes.vercel.app` (or `http://localhost:3000` for staging).
- **Redirect URLs**:
  - `http://localhost:3000/**`
  - `https://aurelia-recipes.vercel.app/**`
  - `aurelia://auth/callback` (Mobile deep link)
  - `aurelia://reset-password` (Mobile password recovery)

### C. User Account Restoration
Refer to `auth/users-inventory.json` in the backup archive:
- Users authenticated via Google OAuth will automatically link their profile upon their first sign-in if the email matches.
- Email/password users can be invited or issued password reset links (`Send Password Reset` via Dashboard) to establish their credentials without manual database manipulation.

## 10. Long-Term Storage & Off-Site Encryption

Since database backups contain user recipes and personal culinary data:
1. **Local Encryption**: Use 7-Zip with AES-256 to password-protect archives:
   ```cmd
   7z a -p -mhe=on "Aurelia_Backup_2026-10-25.7z" "C:\Users\<username>\AureliaBackups\2026-10-25_14-50-25"
   ```
2. **Off-Site Redundancy**: Store the encrypted `.7z` file on a secondary local drive, USB drive, or private cloud storage (e.g., Google Drive / OneDrive). No paid service is required.
